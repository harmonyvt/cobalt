what this mockup does not prove
  • Sketches, not builds. No Swift was written or changed. Effort and performance notes are estimates from reading the current home screen code, not measurements.
  • Sample numbers. Titles and ids come from the app's preview data (the dog at the harbour, the timer one, coffee and the city…). File sizes, lengths, "2 m ago" and the per-day split of the 463.2 MB are made up so the totals add up; the failing link's id is invented.
  • The clipboard state never shows the link. iOS shows a permission prompt when an app reads the clipboard, so the app can only know "there is a link" until you press paste. The mockup keeps to that. The current app reads the clipboard text directly; detecting a link without reading it would be new code.
  • Try again fails again, on purpose. The seeded error is a post with no video in it. Retrying can't fix that, so the mockup counts the attempt and shows the same message. Dismiss is the way out.
  • Convert to webp is instant here. In the app it is a job with its own progress; the mockup only flips the label.
  • Mac is described, not drawn. Each concept's note says how it would lay out in a Mac window; there is no Mac frame in the switcher.
  • Unfolded is drawn flat-landscape with the book fold. Tabletop (fold running left to right) is not drawn; each concept's two halves would stack top and bottom there.
  • Checked by script: every button's action in every concept, screen and state was run against the page's own code (state changes and re-rendered markup asserted), every colour variable resolves in both themes, and text contrast was computed. Layout was checked in headless Chrome screenshots, not on a device.
